# 0.1.5-rc.2 左侧边栏协议（`sidebar.panellist`）调研与 `dsh-tauri-panel-*` 迁移方案

> 状态：**已实施，rc.1 实测通过**（L0–L4 全部落地；实施记录与偏离见第 8 节，版本门槛勘误见第 9 节）。
> 调研基准：核心 `0.1.5-rc.2`（`dependencies/dsh`）对照 `0.1.2-rc.1`（`dependencies/dsh-0.1.2-rc.1-33729514615`）。

> ⚠️ **门槛勘误（第 9 节 + 全文已修正）**：本文最初把 `sidebar.panellist` 等能力
> 写作「0.1.5-rc.2 新增」，**这是错的**——它是 **0.1.5-rc.1** 就引入的（相对
> `0.1.2-rc.1` 是新增）。`0.1.5-rc.1` 与 `0.1.5-rc.2` 在本协议相关能力上逐项一致，
> 正确的门槛一律是 **`≥0.1.5-rc.1`**。详见第 9 节。

## 0. 结论速览

1. **相对 `0.1.2-rc.1`，左侧边栏只新增了一个子槽：`sidebar.panellist`（`list` / `root`）**，
   在 **`0.1.5-rc.1`** 就已引入（`0.1.5-rc.2` 与之一致）。
   它是官方「全局面板」的入口清单，配套的承载槽是同一版本引入的 `main`（`keyed`）。
2. 官方契约形状：
   `ctx.slots.register({ name: 'sidebar.panellist', id, order?, label? }, Icon)`，
   图标组件收到的 ownerProps 是 `{ size: number, active: boolean }`；
   点击由宿主侧 `ctx.layout.selectPanel(id)` 切换到 `main` 里同 key 的面板。
3. **我们的直接损失**：`dsh-tauri-panel` 以 `priority: -1` 整槽 shadow 了官方 `sidebar`，
   克隆侧栏目前**没有渲染 `sidebar.panellist`**。结果是：任何按官方协议注册的插件
   （官方或第三方）条目会注册成功，但左侧栏**没有任何入口 UI**。
4. **间接损失**：`panel.protocol` 的 `openDetails?` / `closeDetails?` 在 0.1.5-rc.1 起
   会静默消失——`ctx.layout.openDetails/closeDetails` 已被 `openRightbar(track, fullscreen)` /
   `closeRightbar()` 取代，`details` 单槽也被 `rightbar` 取代。
5. 迁移分四层，**L1 是必须的保底修复，L2/L3 是协议收敛**，L0 是类型面欠债。

## 3. 官方协议契约（权威摘录）

### 3.1 `sidebar.panellist`

```
kind: list   scope: root
declaredBy: client-ui-sidebar 的 'sidebar' 条目（该条目挂载期间存在）
occupants : 无（纯扩展点，官方自身不注册任何面板）
```

注册选项：

| 名称 | 必填 | 类型 | 语义 |
| --- | --- | --- | --- |
| `id` | ✅ | `string` | 你的 cell 键；**同时用作 `main` 的 key**，自取新 id 追加，复用已占 id 即替换该 cell |
| `order` | — | `number` | 升序排序位，默认 `0` |
| `label` | — | `string \| (() => string)` | 展示文案；thunk 每次投影重读，**因此本地化文案无需重新注册** |

ownerProps（图标组件 props）：

```ts
interface SidebarPanelIconOwnerProps {
  /** 请求的方形边长（px）。 */
  size: number
  /** 该面板当前是否在中间列被选中。 */
  active: boolean
}
```

官方契约给出的最小示例：

```ts
ctx.slots.inject('sidebar.panellist', () => ctx.slots.register(
  { name: 'sidebar.panellist', id: 'my-entry', order: 100, label: 'My entry' },
  () => React.createElement('div', null, 'hello'),
))
```

### 3.2 `main`（panellist 的另一半）

```
kind: keyed   scope: root
已占 key: 'conversation'（client-ui-conversation 注册 ConversationPanel）
replaceRisk: shadows-shipped-ui
```

- `selectPanel(id)` 会先查 `main` 的活条目，**未注册的 id 直接 throw**，当前选中不变。
- `selectPanel(null)` 回到 Conversation，且不改变当前 Session。
- 布局渲染：`renderSlot('main', {}, { entryKey: activePanelId ?? 'conversation' })`
  —— **同一时刻只渲染一个 main 条目**，选中面板时会话整体卸载（与「内容区替换」语义一致）。

### 3.3 官方 `PanelRow` 的渲染方式（我们要复刻的投影）

`dsh-client-ui-sidebar/lib/client.js` 第 104–133 行：

- 每行**订阅自己的选中态**：`const active = usePanelInfo(info => info.activePanelId === id)`。
- 图标经槽内过滤取自己那一条：
  `renderSlot('sidebar.panellist', { size: wide ? 16 : 18, active }, { only: id })`。
- 点击 `selectPanel(id)`。
- 列表为空时**不渲染** `<nav>`（连间距都不占）。
- 列表投影由 `apply()` 里的 `syncPanels` 维护（第 344–362 行）：
  读 `ctx.slots.entriesOfSlot('sidebar.panellist')` → `{ id, order: options.order ?? 0, label: resolveSlotLabel(options.label) ?? id }`
  → 按 order 升序 → 结构相同则跳过写；订阅 `ctx.slots.subscribe('sidebar.panellist', syncPanels)`
  与 `ctx.locale.subscribe(syncPanels)`。

> 官方文案 `「全局面板」`（locale key `sidebar.panels.label`：zh「全局面板」/ en「Global panels」）
> 由 `ui-sidebar` 自己的 `sidebar` NS 提供。

## 4. 我们当前的架构与冲突点

### 4.1 现状（`packages/dsh-tauri-panel`）

- `register/sidebar.ts`：`ctx.slots.inject('sidebar', ...)` 后以 **`priority: -1` 整槽 shadow**
  官方 `ui-sidebar`，组件是 `components/sidebar.tsx` 的 `SidebarRootClone`。
- 克隆侧栏保留官方子槽透传（`<SlotOutlet slotKey="sidebar.workspaces|settings|footer.action|brand.*">`），
  并**唯一新增**私有槽 `sidebar.panel.action`（`list` / root）。
- `register/panel-service.ts`：经 `ctx.reflect.provide('panel.protocol', api)` 暴露
  `ActionItem` / `renderPanelContent` / `closePanelContent`（+ 可选宽度/details 能力），
  由 `service/controller.tsx` 实现「动态 `priority: -1` shadow `main`/`conversation`」的内容区替换。
- 三个消费插件注册 `sidebar.panel.action` 条目，点击调 `renderPanelContent`：
  `dsh-tauri-panel-extension`、`dsh-tauri-panel-placeholder`、`dsh-tauri-panel-scheduler`。
- 0.1.5-rc.1 已做双候选槽适配（`PANEL_VIEW_SEAT_TARGETS`：`conversation` 单槽 / `main` keyed）。

### 4.2 冲突点

| # | 冲突 | 影响 |
| --- | --- | --- |
| C1 | 克隆侧栏不渲染 `sidebar.panellist` | 按官方协议注册的插件**有注册、无入口**（静默失效，无报错） |
| C2 | 两套面板协议并行（`sidebar.panel.action` vs `sidebar.panellist`） | 生态困惑；官方文档推荐路径在我们的壳里不可用 |
| C3 | `openDetails?` / `closeDetails?` 在 rc.2 静默消失 | 消费方 `?.()` 探测后变成 no-op；右侧能力实际不可用 |
| C4 | 仓库 devDeps 类型面滞后 | `@deepseek-ai/dsh-client-ui-layout` 解析到 `0.1.0-rc.8`（无 `selectPanel`、仍是 `details` 语义）；`dsh-client-ui-slots` 解析到 `0.1.2-alpha.3`（`SlotMap` 为空表）→ 现有代码通篇 `as never` |
| C5 | `sidebar.panellist` 的**声明者是被我们 shadow 掉的官方条目** | 我们依赖「被 shadow 条目的 children 声明仍然有效」这一语义（`workspaces`/`settings` 已上线验证），本次不新增风险但会放大 |

C5 的说明：官方槽位登记表对 `sidebar` 的描述是
「registering here replaces the navigation column outright … **and the seats it declares disappear with it**」。
这句话描述的是**渲染面**（官方 AppFrame/SidebarRoot 不再渲染那些 seat），不是注册面的撤销；
`sidebar.workspaces` / `sidebar.settings` / `sidebar.footer.action` 经 `<SlotOutlet>` 透传已在线上验证可用，
`sidebar.panellist` 是同一张 `children` 表里的兄弟键，行为一致。**但要作为回归项显式验证。**

## 5. 迁移方案

### L0 — 类型面（建议，可与 L1 并行）

二选一：

1. **升 catalog**（推荐）：把 `pnpm-workspace.yaml` 的 `catalog:dsh` 中
   `@deepseek-ai/dsh-client-ui-layout`、`@deepseek-ai/dsh-client-ui-slots`、
   `@deepseek-ai/dsh-client-ui-renderer` 提升到 `0.1.5-rc.2`，让 `ILayout.selectPanel`、
   `main`/`sidebar.panellist` 的 `SlotMap` 合并、`SidebarPanelIconOwnerProps` 直接可用，
   并逐步去掉 `as never`。风险：范围较大，会牵动其他插件（`dsh-tauri-ui`、`turnrewind` 等）的类型。
2. **补 ambient stub**（最小改动）：在 `types/stubs/` 下新增 `dsh-client-ui-slots.d.ts`，
   按现有 `types/slot-outlet.d.ts` / `types/stubs/*.d.ts` 的模式声明
   `SlotMap['sidebar.panellist']`、`SlotMap['main']`、`SidebarPanelIconOwnerProps`、
   `resolveSlotLabel`、`SlotCore.entriesOfSlot/subscribe`；并在
   `packages/dsh-tauri/src/client/types/inject.ts` 里用 `Omit`/交叉补丁给 `ILayout` 加
   `selectPanel?(id: string | null): void`。

无论哪条路，`packages/dsh-tauri/src/client/types/context.ts` 的 `ClientSlots` 都必须扩展：

```ts
export interface ClientSlots {
  inject: (slot: string, setup: () => unknown) => () => void
  register: (slot: unknown, component: unknown) => () => void
  /** 读 list/keyed 槽的活条目投影（`sidebar.panellist` 投影用）。 */
  entriesOfSlot: (slot: string) => readonly SlotEntryLike[]
  /** 订阅槽位变化（声明/注册/注销都会触发）。 */
  subscribe: (slot: string, listener: () => void) => () => void
}
```

### L1 — 宿主克隆渲染 `sidebar.panellist`（**P0，必做**）

目标：官方/第三方按 `sidebar.panellist` 注册的面板，在我们克隆的侧栏里出现完整入口。

改动点（`packages/dsh-tauri-panel`）：

1. **新增 `src/client/service/panel-list.ts`** —— 复刻官方 `syncPanels` 投影：

   ```ts
   // 读 entriesOfSlot('sidebar.panellist') → { id, order, label }
   // label 用 resolveSlotLabel（thunk 跟随语言）
   // 按 order 升序；结构相同不写 store
   // 订阅 ctx.slots.subscribe('sidebar.panellist') + ctx.locale.subscribe
   ```

   落到 `createExternalStore`（`dsh-tauri/client`），由 `register/sidebar.ts` 的
   `inject` 以 `hooks: { panels }` 形式交给组件（对齐官方形状，便于将来直接吃官方实现）。

2. **`src/client/register/sidebar.ts`** —— `inject` 增加：

   ```ts
   selectPanel: (id: string) => { ctx.layout.selectPanel?.(id) },
   hooks: { panels: panelListStore },
   ```

   组件里再加 `usePanelInfo`（由框架标准 prop 自动注入，无需 inject）。

3. **`src/client/components/sidebar.tsx`** —— 在 panel-area 内、`sidebar.panel.action` 旁渲染
   `panellist` 行（复刻官方 `PanelRow` 的语义：`aria-current`、折叠态 Tooltip、
   `size: wide ? 16 : 18`、`active`），图标经
   `<SlotOutlet slotKey="sidebar.panellist" ownerProps={{ size, active }} opts={{ only: id }} />`。
   **列表为空时不渲染 `<nav>` 与间距**（保持官方行为，避免空档）。

4. **`src/client/types/index.ts`** —— `SidebarRootProps` 增加
   `selectPanel`、`usePanelInfo`、`panels`；新增 `PanelListEntry` / `PanelRowProps` 类型。

5. **降级**：`ctx.layout.selectPanel` 不存在（≤0.1.2-rc.1 核心）时不渲染 panellist 行；
   该核心下 `sidebar.panellist` 本就未声明，`entriesOfSlot` 返回空表，双保险。

6. **DOM 兼容锚点复核**：`PANEL_SIDEBAR_COMPAT_CLASS` 现有约定是
   「纯 Web 插件的注入行落入 panel-area 与 region-area 之间」。
   panellist 行并入 panel-area 后，顺序应保持
   `新会话 → 官方 panellist → 私有 sidebar.panel.action → （纯 Web 插件 DOM 注入行）→ workspace 浏览器`。
   需同步更新 `constants/index.ts` 的注释与 `PROTOCOL.md` 第 5 节。

### L2 — 三个消费插件迁到官方协议（P1）

`dsh-tauri-panel-extension` / `-placeholder` / `-scheduler` 的 `register/*panel*` 改为：

```ts
// 图标（active 由 owner 传入，无需自建选中态 store）
ctx.slots.inject('sidebar.panellist', () => ctx.slots.register(
  { name: 'sidebar.panellist', id: PANEL_ID, order: PANEL_ORDER, label: () => t('scheduler') },
  ({ size, active }) => <PanelIcon size={size} active={active} />,
))

// 内容（与 panellist 同 id 作为 main key）
ctx.slots.inject('main', () => ctx.slots.register(
  { name: 'main', key: PANEL_ID },
  PanelBody,
))

// 点击
ctx.layout.selectPanel(PANEL_ID)
```

要点：

- `label` 必须用 **thunk** 才能跟随语言切换（`resolveSlotLabel` 每次投影重读）。
- `main` 条目是 `root` scope，**不带 Session 绑定**；面板体自己从 `useSessions` 取当前会话
  （现有 `SchedulerPanel` / `ExtensionPanel` 已是自取数据，影响可控）。
- `main` 的 key 已占 `conversation`，面板 id 需避开。
- **双核心并存**：官方协议只存在于 ≥0.1.5-rc.1；旧核心仍需 `sidebar.panel.action`。
  建议抽一个统一适配器（新文件，如 `packages/dsh-tauri-panel/src/client/register/panel-entry.ts`）：

  ```ts
  registerPanelEntry(ctx, { id, order, label, icon, body })  // 内部按核心能力择一注册
  ```

  判据：`typeof ctx.layout.selectPanel === 'function'` 且 `ctx.slots.entriesOfSlot('sidebar.panellist')`
  可用 → 官方路径；否则回退 `panel.protocol` + `sidebar.panel.action`。
  这样三个插件各自只调一次，协议分支收敛在一处。

### L3 — `panel.protocol` 兼容层改造（P2）

`packages/dsh-tauri-panel/src/client/service/controller.tsx` + `register/panel-service.ts`：

1. `renderPanelContent(spec)` 新核心路径改为
   **动态注册 `main` key = `spec.id` + `ctx.layout.selectPanel(spec.id)`**，
   不再 shadow `conversation`；旧核心保留既有 shadow 实现（`PANEL_VIEW_SEAT_TARGETS` 逻辑不动）。
   好处：内容区替换与官方面板走同一套选中态，`usePanelInfo().activePanelId` 对两者都成立。
2. `closePanelContent()` 新核心改为 `ctx.layout.selectPanel(null)`（回到会话，不换 Session）。
3. `ActionItem` 的 active 态：新核心优先用 `usePanelInfo`，旧核心保留 `panelViewStore` 回退。
4. `openDetails?` / `closeDetails?`：**不要**把新语义塞进旧名字。建议
   - 保留旧字段（旧核心仍有 `details` 列），
   - 新增可选 `openRightPanel?()` / `closeRightPanel?()`，内部委托
     `ctx.layout.openRightbar(track, fullscreen)` / `closeRightbar()`。
   `openRightbar` 是**报告式**（告诉 frame 右侧栏占不占 track、是否全屏），
   不是「打开/关闭」开关，语义必须写进 `PROTOCOL.md`。
5. `PROTOCOL.md` 增加第 6 节，明确：
   - `sidebar.panellist` + `main` 是**官方推荐路径**；
   - `sidebar.panel.action` + `panel.protocol` 降级为**兼容/私有协议**，新插件应优先官方；
   - 两套协议在宿主内共用同一选中态（`activePanelId`），可安全混用。

### L4 — 文档与契约同步（P3）

- `packages/dsh-tauri-panel/PROTOCOL.md`：新增官方协议章节 + 右侧栏语义变更。
- `packages/dsh-tauri-panel/README.md`：能力表补充「官方全局面板入口」。
- `packages/dsh-tauri-panel-extension|placeholder|scheduler/README.md`：接入方式改为官方协议。
- `docs/AGENTS.plugins.md`「Slot 与组件协议规则」：补一句「跨核心版本的面板入口走
  `registerPanelEntry` 适配器，不直接写死槽名」。

## 6. 风险与验证

### 6.1 风险

| 风险 | 说明 | 缓解 |
| --- | --- | --- |

### 8.2 与方案的偏离

1. **L2 没有新建 `registerPanelEntry` 适配器模块，而是扩了 `panel.protocol`**。
   方案原设想让三个插件 import 一个共享适配器；实际改为
   `panel.protocol.registerPanel(entry)`——三个插件本来就经反射服务消费宿主，
   这样**零新增跨包依赖**，双核心分支也只存在于宿主一处；且存量的第三方
   `panel.protocol` 消费者只要改用 `registerPanel` 就自动获得官方全局面板身份。
2. **`label` 用 thunk 而非快照**：`registerPanel` 的 `label` 透传给官方
   `sidebar.panellist`，由官方 `resolveSlotLabel` 读时求值，语言切换无需重新注册。
   旧核心回退路径（`ActionItem`）无法重投影，故在注册时求值一次，已在代码注释标注。
3. **`renderPanelContent` 在官方核心上不再 shadow `conversation`**，而是注册
   `main` 的 `spec.id` cell 并 `selectPanel(spec.id)`。好处是内容区替换与官方
   全局面板共用 `activePanelId` 这一个选中态源；`close()` 显式
   `selectPanel(null)` 归还。
4. **`closePanelContent()` 额外归还官方选中态**（`ctx.layout.selectPanel?.(null)`）：
   经 `registerPanel` 注册的面板不经过控制器，若不归还，「面板内跳转到会话」
   的动作在官方路径下会变成 no-op。
5. **右侧栏新增 `openRightPanel` / `closeRightPanel` 而非复用旧名**：新语义是
   **报告式**（占不占 track / 是否全屏），与旧 `openDetails` 的开关式不同，
   复用旧名会造成误导；两者按 `ctx.layout` 实际能力分别提供。
6. **`resolveSlotLabel` 用本地等价实现**（`typeof label === 'function' ? label() : label`）
   而不是 import 平台模块 `@deepseek-ai/dsh-client-ui-slots`，避免为类型面再引入
   ambient stub；语义与上游逐字一致。

### 8.4 验收反馈修复：面板行退化为浏览器默认样式

**现象**（用户验收发现）：侧栏出现两个「扩展 / 定时任务」入口，但都是 HTML 默认按钮外观。

**根因**：`.dshp-panel__menu-item` / `__menu-item-icon` / `__menu-item-label` 三组行样式
定义在 `components/action-item.cssr.ts`，历史上**只由 `PanelActionItem` 组件经
`useMountStyle` 挂载**。三个消费插件迁到 `registerPanel` 后，新核心走官方
`sidebar.panellist`+`main`，`sidebar.panel.action` 槽不再有条目 → `PanelActionItem`
永不渲染 → 这份样式从未挂载；而新加的 `components/panel-row.tsx` 直接复用了
`.dshp-panel__menu-item` 类名 → 裸奔成浏览器默认按钮。

> 这个缺陷在 L1/L2 的单元测试里测不出来：cssr 样式挂载是运行时副作用，而现有
> 测试要么 mock 掉 `useMountStyle`（`controller.test.ts`），要么不渲染组件。
> 教训：**跨组件复用的 class 名必须由「总是挂载的那一方」持有样式**。

**修复**：由克隆侧栏（`components/sidebar.tsx`，只要插件启用就必然渲染）统一挂一份
`action-item.cssr`（`useMountStyle(actionItemStyle, ACTION_ITEM_STYLE_ID)`）。
`mountStyle` 是引用计数幂等的，与 `PanelActionItem` 自身的挂载互不冲突（同 CNode +
同 style id 只产生一个 `<style>`，两边都只挂一次）。

**复核**：面板包内其余样式挂载点已逐一确认不再有此问题——
`styles/index.cssr.ts` 在 `apply()` 挂载（常驻）、`conversation-seat.cssr.ts` 由
`ConversationSeat` 自挂（官方路径下仍渲染）、`sidebar.cssr.ts` 由克隆自挂、
`Icon` 为纯 SVG 无 cssr。

## 9. 版本门槛勘误（重要）

本文档以及同期落地的 `PROTOCOL.md`、代码注释，最初把这条协议的门槛写成
**`≥0.1.5-rc.2`**。**这是错的**，已全部修正为 **`≥0.1.5-rc.1`**。

### 9.1 错误是怎么产生的

调研时只读了 `dependencies/dsh`（`@deepseek-ai/dsh@0.1.5-rc.2`）与
`dependencies/dsh-0.1.2-rc.1-33729514615` 两侧，**没有读同目录下已经安装的
`dependencies/dsh-0.1.5-rc.1-34455899979`**，于是从「rc.1 有 `main`/`selectPanel`、
rc.2 才谈 panellist」推断出「panellist 是 rc.2 新增」。属于未经核实的推断。

### 9.2 核实结果（`dsh-0.1.5-rc.1-34455899979`，`@deepseek-ai/dsh@0.1.5-rc.1`）

| 检查项 | rc.1 | rc.2 |
| --- | --- | --- |
| 侧栏壳 `"sidebar.*"` 键集 | brand.mark / brand.name / footer.action / **panellist** / settings / workspaces | 同 |
| 侧栏渲染侧 `panelList` / `panelRow` / `usePanelInfo` / `panels.label` / `entriesOfSlot` | 全部 YES | 全部 YES |
| 布局顶层槽 | sidebar / main / rightbar / shell.overlay | 同 |
| `ctx.layout` | `selectPanel` ✅、`openRightbar` ✅、`closeRightbar` ✅、`openDetails` ❌、`closeDetails` ❌ | 同 |
| `provideRoot` / `panelInfo` | YES | YES |

**结论**：`0.1.5-rc.1` 与 `0.1.5-rc.2` 在本协议相关能力上逐项一致；`sidebar.panellist`
是 `0.1.5-rc.1` 引入的（相对 `0.1.2-rc.1` 新增）。运行时**没有任何回归**——代码走的是
能力探测（`typeof ctx.layout.selectPanel === 'function'`），从不硬编码版本号；错的只是
文档与注释里的门槛表述。
