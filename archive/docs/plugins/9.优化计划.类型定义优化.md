# 9. 优化计划 · 插件类型定义优化（手写型收敛到 dsh-tauri + 官方来源）

> 状态：**计划** · 关联：`docs/AGENTS.plugins.md`、`docs/AGENTS.desktop.md`
>
> 核心诉求（用户原话摘引）：「所有插件的类型定义都是手写类型，也没有引用来源，非常不可靠，
> 且 Agent 得到的信息也少，也更容易出错」。

---

## 0. TL;DR

- **痛点**：全 workspace 大量 `src/client/types/*`、`src/host/types/*` 里手写了与 `@deepseek-ai/*`
  **官方类型重复/近似**的接口（`SessionListSnapshot`、`WorkspaceListSnapshot`、`SessionSummary`、
  `JsonValue`、`ToolRunContext`、`ModelSelection` 等），没有来源标注、字段不全、版本漂移。
- **方案**：所有 `@deepseek` 相关类型**优先使用官方可导出的类型**，统一收口到
  `packages/dsh-tauri/src/client/types/`（客户端）与 `packages/dsh-tauri/src/host/types/`（宿主）。
  子模块一律 `import type { ... } from 'dsh-tauri'`（客户端从 `dsh-tauri/client`）。
- **硬约束**：`packages/*/src/host/` 禁止静态引用任何 `@deepseek-ai/*` **运行时**包；仅允许
  **type-only import**，否则打包进独立 `resources/node_modules` 会引入运行时依赖。
- **文档要求**：类型必须标注**来源（source）/ 版本（version）/ 修订变更范围**；字段描述尽量齐全。

## 1. 背景与问题分析

### 1.1 现状盘点（已调研确认）

当前 `packages/*` 存在两类手写类型：

1. **官方可替代类**：与 `@deepseek-ai/*` 已发布 d.ts **语义重复或近似**，属冗余手写，应替换为官方类型。
2. **桌面端专属 / 协议类**：官方没有对应导出（如 Tauri bridge、归档页载荷、面板协议），
   **保留手写但必须收口到 dsh-tauri 并标注来源**。

已确认的官方可替代手写点：

### 1.3 host 依赖边界（不可违反）

`docs/AGENTS.desktop.md` 明确：

> 内置插件 host 依赖边界：`packages/*/src/host/` 运行在独立的 `resources/node_modules` 中，
> **禁止直接静态引用任何 `@deepseek-ai/*` 运行时包**（包括 `import`、`export ... from` 和 `require`）；
> 必须通过宿主上下文的 `loader.import()` 解析 DSH-owned 模块。
> **`@deepseek-ai/*` 仅可作为 host 的 type-only import，不能产生运行时依赖。**

结论：host 侧引入官方类型**只能用 `import type { ... } from '@deepseek-ai/...'`**，且不能经 barrel 形成运行时引线。
`import type` 在编译后被擦除，不产生运行时依赖，安全。

## 2. 目标结构

所有 `@deepseek` 相关类型统一收口到 **`dsh-tauri`**，子模块用 `import type { ... } from 'dsh-tauri'`
（客户端子路径 `dsh-tauri/client`）。

```
packages/dsh-tauri/src/
├─ client/types/                     # 客户端类型（kebab 文件，barrel 聚合）
│  ├─ index.ts                       # 唯一 public barrel：export * from './bridge' 等
│  ├─ context.ts                     # ClientContext（Context & { locale; layout }）——保留
│  ├─ runtime.ts                     # ISessions / IWorkspaces / SessionListState / SessionSummary /
│  │                                  #   WorkspaceId -> 一律从 @deepseek-ai/dsh-*-controller/client type-only re-export
│  ├─ inject.ts                      # ILayout（从 dsh-client-ui-layout/client re-export）+ LocaleService
│  ├─ bridge.ts                      # NavBridgeHandlers / Page / ErrorAction（Tauri 专属，保留手写，标注来源）
│  ├─ global.ts                      # Window 增广（__dsh_tauri_bridge__）——保留
│  ├─ slots.ts                       # dsh-client-ui-slots 槽标准 props alpha 兼容增广——保留/重审
│  └─ (新增) agent.ts                # ModelSelection / ToolExecution / ToolRunContext type-only re-export
│  └─ (新增) json.ts                 # JsonValue / SessionId / WorkspaceId type-only re-export
├─ host/types/                       # 宿主侧类型（若有官方可复用，type-only；否则手写收口）
│  └─ index.ts                       # HttpStatic/ClientContext(host) 等
```

**导入规约**：

- 官方存在 → `dsh-tauri`/`dsh-tauri/client` 从 `@deepseek-ai/*` **`import type { ... }` 后 re-export**；
  插件从 `dsh-tauri` / `dsh-tauri/client` 导入，**不直接** `import type from '@deepseek-ai/*'`（收敛来源）。
- 官方缺失 → 手写定义在 `dsh-tauri/src/{client,host}/types/`，**文件头块注释标注**：
  `来源`（官方包名+无该导出，或协议自报）、`版本`（参照的官方包版本）、`修订`（本次变更范围）。
- 插件 `src/client/types/` 与 `src/host/types/` **不再**手写与官方重复的类型；只保留插件私有领域类型。

## 3. 类型来源标注规范

每个定义（尤其手写 fallback）必须带上如下的**块注释头**（统一模板）：

```ts
/**
 * 【来源】https://github.com/deepseek-harness/... （或：桌面端自报协议，官方 @deepseek-ai/dsh-* 无对应导出）
 * 【版本】参考 @deepseek-ai/dsh-session@0.1.0-rc.8 的 lib/types/types.d.ts
 * 【修订】2026-01-xx：由 dsh-tauri-panel-scheduler/src/types/dsh.d.ts 迁入；字段与官方 JsonValue 对齐。
 */
```

**字段描述要求**：复杂载荷每个字段给 `/** ... */` 说明**语义/边界/可选条件**（如「absent while undeclared」、
「undefined 表示未分组」），供 Agent 决策时读到足够语义，减少臆测。

## 5. 执行步骤

1. **dsh-tauri 加 devDependencies**（若需新增官方包引用）：在 `packages/dsh-tauri/package.json`
   `devDependencies` 追加 `@deepseek-ai/dsh-session`、`@deepseek-ai/dsh-tools`、`@deepseek-ai/dsh-agent`、
   `@deepseek-ai/dsh-workspace`、`@deepseek-ai/dsh-storage-domain`（均取 `catalog:dsh`）。
   注意：`dsh-tauri` 是 **runtime** 依赖的宿主工具包，这些 `@deepseek-ai/*` 必须只进 `devDependencies`
   并只作 type-only 引用，**绝不能进 `dependencies`**，否则破坏 host 依赖边界。
2. **新增 `client/types/json.ts`**：type-only re-export `JsonValue`、`SessionId`、`WorkspaceId`。
3. **新增 `client/types/agent.ts`**：type-only re-export `ModelSelection`、`ToolExecution`、`ToolRunContext`。
4. **改造 `client/types/runtime.ts`**：从官方 controller re-export `ISessions`/`IWorkspaces`/`SessionListState`/`SessionSummary`/`WorkspaceId`；移除重复手写投影或改名为桌面专属别名。
5. **更新 `client/types/index.ts`** barrel 追加 `./json`、`./agent`。
6. **插件侧**：把 `dsh-tauri-session`、`dsh-tauri-panel-scheduler` 等处手写句点改为 `import type { SessionSummary, JsonValue, ModelSelection, ToolExecution } from 'dsh-tauri'`（host 侧从 `dsh-tauri` 根；client 侧从 `dsh-tauri/client`）。

8. **补来源标注**：所有仍手写的类型补块注释头（来源/版本/修订）。
9. **验证**：`pnpm --filter dsh-tauri typecheck`、`pnpm --filter <pkg> typecheck`、`pnpm run lint --fix`、相关 build；`pnpm typecheck`（前端）。
10. **回归**：确认 `dsh-tauri/dist/index.d.ts`、`dist/client.d.cts` 重新生成后导出面符合预期；host 打包产物 `resources/node_modules` 不含 `@deepseek-ai/*` 运行时。

## 7. 已知风险 / 待决

- **alpha vs rc 版本漂移**：`dsh-client-runtime`、`dsh-client-ui-*` 为 `^0.1.2-alpha.2`，类型仍在演进；
  迁移前须以当前 lockfile 实际解析版本为准，避免引用已改名 seat。
- **`SessionListState` vs 手写 `SessionListSnapshot` 形状差异**：官方带 `subagentsByParent`、`jobsBySession`、
  `currentAddress` 等富字段，替换后消费点可能需补齐读取；评估是否缩小替代（只取所需子面）。
- **`dsh-tauri` 是否把官方类型推进 `dependencies`？** 结论：**否**，只能 `devDependencies` + type-only；
  若未来某插件 client 需要 `@deepseek-ai/*` 的运行时值，走 `dsh-tauri` 的 `dsh.client.inject` 注入而非直接 import。
