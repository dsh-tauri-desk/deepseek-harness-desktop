### DSH 架构与代码职责重构方案（全面并行推进）

### 一、 重构核心原则与定位

* **核心主线**：代码职责重构，不涉及 package 发布配置调整。
* **架构模式**：严格保留现有 DSH 的 `host half / client half` 边界。
* **拆分策略**：按真实业务领域内聚拆分，拒绝机械创建 `utils/services` 目录。
* **工具态度**：UnJS 体系工具仅按需针对性使用，不进行批量替换。
* **当前状态**：暂未修改代码，准备全量实施。

### 三、 重点开源范式参考

* **架构与领域组织**
* **[antfu-collective/taze](https://github.com/antfu-collective/taze)**：按 `manifests`、`registries`、`commands` 等领域平铺划分。
* **[antfu-collective/vite-plugin-inspect](https://github.com/antfu-collective/vite-plugin-inspect)**：隔离 Node 宿主与 Client 双运行时边界。
* **[antfu-collective/birpc](https://github.com/antfu-collective/birpc)**：分离 RPC 协议、消息与工具逻辑。
* **[antfu-collective/install-pkg](https://github.com/antfu-collective/install-pkg)**：小规模模块按单一职责平铺。
* **[antfu-collective/unconfig](https://github.com/antfu-collective/unconfig)**：仅存在稳定共享底层能力时才抽离独立 core 包。

- 重点参考文件目录规划，文件命名，代码规划、架构设计、模块拆分策略。

* **候选工具库 (UnJS)**
* **[pathe](https://github.com/unjs/pathe)**：规范化跨平台路径处理。
* **fetch**：类型友好的 HTTP 请求工具。
* **[hookable](https://github.com/unjs/hookable)**：精细化生命周期与事件钩子管理。
* **[unstorage](https://github.com/unjs/unstorage)**：统一低风险缓存层。
